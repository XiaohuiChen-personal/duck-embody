Duck Embody — Low-Level Design Docs

Design-doc index - 2026-07-26

APPROVED — owner-approved 2026-07-26. Deviations during implementation must update this doc in the same commit.

Duck Embody puts a frontier LLM in control of the Open Duck Mini v2 — a 42 cm bipedal robot — inside an unknown duck-scale apartment in Isaac Sim: the model issues tool calls that drive a pretrained RL locomotion policy (v4_robust, PPO), and there is no classical SLAM anywhere — the LLM authors its own map as text, dead-reckons its position from commanded velocity, and corrects drift cognitively via loop-closure tools. Three models (Fable 5, Opus 5, GPT 5.6 sol) attempt the same two-stage task (find_kitchen, then return_home) over the same four seeds under one frozen prompt/camera/tool configuration; scoring compares success, path efficiency, map accuracy, and dead-reckoning drift against the layout ground truth. The project is inspired by Anthropic's "How Claude Performs on Robotics Tasks" (Jul 2026; their harness is unreleased) and doubles as a portfolio piece and a sim prototype for the parent robot project's Phase 5.

Rules vs. designs: AGENTS.md at the repo root is the binding rules source — hard rules, locked decisions, and canonical constants. The documents below are the per-component low-level designs built under it. Where any design doc and AGENTS.md disagree, AGENTS.md wins and the doc must be fixed.

Canonical constants (quick reference)

Values below restate the canon in AGENTS.md; every design doc must agree with them exactly.

ItemCanonical value
Models (locked)Fable 5 (claude-fable-5, Anthropic) · Opus 5 (claude-opus-5, Anthropic) · GPT 5.6 sol (OpenAI). One prompt, one camera config, one tool set — no per-model tuning.
Taskfind_kitchen ("Find the kitchen and walk to the counter"), then continuation return_home in the same episode.
Success radiifind_kitchen: base within 0.35 m of the kitchen-counter target region + declare_done · return_home: within 0.5 m of spawn + declare_done.
Seeds / trialsN=4 fixed seeds {101, 102, 103, 104}, identical across models (seed → spawn point + heading from the layout's spawn_points); 3 models × 4 seeds = 12 trials, sequential in ONE persistent Isaac Sim process.
Caps (per stage)40 model turns · 240 policy-seconds of commanded motion · a fall ends the trial. Cap hits and timeouts are scored failures, never selectively retried.
Command hullvx ∈ (−0.148, 0.222) m/s · vy ∈ (−0.111, 0.111) m/s · wz ∈ (−0.5, 0.5) rad/s — everything clamped; vy is near-useless (~9 s/m), prefer turn-then-drive.
Control / sim50 Hz control (sim dt 0.005 s × decimation 4); duration_s → N = 50 × duration_s steps; sim PAUSES between LLM calls (capability, not latency).
Policyv4_robust (RSL-RL PPO, model_2999.pt, vendored into policy/); 59-dim actor obs (ang_vel 3, gravity 3, commands 3, joint_pos 16, joint_vel 16, actions 16, gait_phase 2 — no base_lin_vel); normalization baked in, never pre-normalize; eval record 5/5 gait gate, 0.00% falls / 3,200 episodes.
Camera (frozen)Head-mounted egocentric, ~0.36 m height, 512×512 RGB, 90° horizontal FOV (smoke-test adjustable only BEFORE freeze), 1 frame per get_observation.
SceneDuck-scale 0.4×; apartment 4.8 × 3.6 m; rooms living_room / kitchen / bedroom / hallway; walls 0.5 m high / 0.03 m thick; doorways 0.35 m (duck body ~0.16 m); target = kitchen counter (Sektion_Cabinet run).
Tools (canonical names)get_observation · look_around · turn_to_heading(heading_deg) · move(distance_m) · send_velocity(vx, vy, wz, duration_s) · update_room · add_landmark · mark_exit · set_current_room · correct_position(x, y, reason) · update_plan · declare_done.
Context policySystem prompt + first turn + last K=10 turns kept; memory block re-injected EVERY turn; images older than K turns dropped.
Memory principle"The harness stores and formats; the LLM perceives, estimates, and decides." Declared sensor-realistic exceptions: compass heading (BNO055-realistic), dead-reckoned position from commanded velocity, closed-loop macros. Ground truth is NEVER shown to the model. Map rendered in MapGPT grammar.
MetricsSuccess rate · progress = clip(1 − d_final/d_initial, 0, 1) · SPL = S·l/max(p, l) · time-to-kitchen (policy-seconds) · turns used · bumps · falls · map accuracy (room-node P/R + adjacency edge accuracy) · dead-reckoning drift at goal · post-episode layout QA (5 fixed questions). Mean ± bootstrap 95% CI over N=4, per-trial table always shown.
RuntimeDGX Spark (aarch64, single GB10 GPU, headless); Isaac Sim 5.1.0-rc.19; Isaac Lab 2.3.2; ONE Isaac Sim / GPU job at a time; parent repo read-only; API keys via env vars only.
